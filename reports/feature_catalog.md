## 4. Point-in-time guarantees

- Behavioural features use only interactions with `timestamp <= as_of`; adding or changing any later (test-period) interaction cannot change a feature value (covered by `tests/test_features.py`).
- Recency/tenure features are measured relative to `as_of`, never to the wall clock.
- Every table carries `feature_timestamp` (= as_of) and `feature_set_version`; the store refuses to serve a feature set whose version differs from `features.feature_set_version` in the config.
- Tables are validated against the registry (columns, dtypes, unique keys, no nulls) before being written and again when the store loads them.
